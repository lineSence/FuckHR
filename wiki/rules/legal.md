# Правила: юридика и данные

> Главный практический риск проекта — не техническая сложность, а право.

### [LEG-001] Законный потолок по данным о людях
Собираем: должность, публичный профиль, корпоративный email, общий телефон компании.
Не собираем: личные мобильные, личные соцсети, домашние адреса. Основание: 152-ФЗ, GDPR.
Статус: validated → core `[CORE-013]`

### [LEG-002] API вместо скрейпинга
Скрейпинг hh.ru и LinkedIn нарушает их ToS. Приоритет: hh.ru Open API; для западных — публичные API ATS (Greenhouse, Lever, Ashby).
Статус: validated → core `[CORE-014]`

### [LEG-003] Обход защит не входит в скоуп
Антикапча, подделка сессий и массовые автоотклики — вне скоупа. В 2026 растут системы детекции автооткликов — это ещё и вредит кандидату.
Статус: validated

### [LEG-004] Статус источника фиксируется рядом с данными
Любой факт в досье хранит источник и дату. Без источника факт не показывается пользователю как утверждение.
Статус: validated

### [LEG-005] Популярность репозитория ≠ легальность подхода
Пример: `freellmapi` (26k+ ★) помечен автором как «personal experimentation only»; `llm-keypool` и `freeflow-llm` реализуют запрещённую `[LLM-003]` ротацию ключей.
Статус: validated
