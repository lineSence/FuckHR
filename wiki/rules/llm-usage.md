# Правила: работа с LLM и квотами

### [LLM-001] Единая точка входа — LiteLLM
Контекст: любой вызов модели из агентного кода.
Правило: код знает один OpenAI-совместимый endpoint; список моделей и фолбэки — только в конфиге LiteLLM.
Статус: validated

### [LLM-002] Провайдер не выбирается «один на всё»
Правило: общая цепочка фолбэков для всех шагов — ошибка. Каждый этап пайплайна имеет свою пару «основной → фолбэк» (см. `wiki/architecture/model-routing.md`).
Статус: validated

### [LLM-003] Запрет на ротацию аккаунтов одного провайдера
Контекст: соблазн сделать пул ключей («3 ключа Gemini = 4500 запросов/день»).
Правило: запрещено — это нарушение ToS Google/Groq/OpenRouter и путь к бану. Замена: ротация разных провайдеров + Ollama.
Источник: сверка ответов LLM (Opus/Kimi/Groq против Deepseek).
Статус: validated → core `[CORE-011]`

### [LLM-004] Каскад по сложности
Правило: дешёвые/быстрые модели отсеивают 80–90% вакансий; дорогие по квоте работают с оставшимися 10–20%. Лимит «умного» оркестратора — 100–300 вызовов/день.
Статус: validated

### [LLM-005] Детерминированный код вместо LLM
Правило: зарплатный порог, гео, ключевые слова, дедуп по хэшу описания — обычным Python до любого LLM-вызова.
Статус: validated

### [LLM-006] Кэш по хэшу промпта
Контекст: в мониторинге 60–80% запросов — повторные вакансии.
Правило: дисковый кэш ответов обязателен — экономит лимиты сильнее любой ротации.
Статус: validated

### [LLM-007] Переключаться до 429
Правило: свой счётчик квот + circuit breaker + cooldown + асинхронная очередь с backoff. Один «умный» проход по вакансии = 4–10 вызовов, при 10–30 RPM минутный лимит наступает раньше суточного. Параллелизм 1–2 воркера.
Статус: validated

### [LLM-008] Требования к провайдеру
Правило: провайдер годится, если есть OpenAI-совместимый `/v1/chat/completions`, tool/function calling, JSON-output, внятный RPM (а не только RPD) и стабильный base URL.
Статус: validated

### [LLM-009] Градуальная деградация
Правило: падение или бан одного провайдера снижает качество вывода, но не останавливает пайплайн. Квоты режут без предупреждения.
Статус: validated

### [LLM-010] Локальная модель — последний рубеж, не основа
Контекст: спор «Ollama как основной мозг» против «Ollama как фолбэк».
Правило: облако — основа, Ollama — обязательный последний слот. Модель 8–14B с работающим tool calling, не 1–3B. Схема «локаль как основа» требует отдельного железа под инференс.
Статус: validated

### [LLM-011] Не гонять персональные данные через обучающиеся free-тиры
Правило: данные о конкретных людях обрабатываются локальной моделью либо вообще не отдаются в LLM.
Статус: validated → core `[CORE-012]`
