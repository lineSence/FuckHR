# Архитектура: обзор

## Контекст

Однопользовательская система для соискателя. Фоновые агенты собирают вакансии, проверяют работодателя и присылают дайджест в Telegram. Всё работает на бесплатных LLM-квотах с локальным фолбэком.

## Модули

| Модуль | Ответственность | Зависимости |
| --- | --- | --- |
| `collectors` | Сбор вакансий: hh.ru Open API, ATS-адаптеры, карьерные страницы | источники из `references/data-sources.md` |
| `prefilter` | Детерминированный отбор и дедуп без LLM | — |
| `extractor` | Извлечение полей из HTML/текста в JSON | LiteLLM |
| `hr_detector` | Проверка утверждений вакансии | `company_intel`, LiteLLM |
| `company_intel` | Сбор досье: отзывы, история вакансий, публичные контакты | БД, LiteLLM |
| `scorer` | Итоговый скор и карточка | LiteLLM |
| `notifier` | Дайджест в Telegram | Telegram Bot API |
| `llm_gateway` | Конфиг LiteLLM, счётчик квот, circuit breaker, кэш | провайдеры |
| `store` | SQLite/Postgres: вакансии, история публикаций, кэш, досье | — |
| `scheduler` | APScheduler: ночной обход и батчи | — |

## Границы системы

- Вне скоупа: автоотклики, обход капчи, сбор личных контактов людей.
- Один пользователь, одна машина, без мультитенантности.

## Решения (ADR)

- **ADR-001. LiteLLM как единый шлюз.** Контекст: требование менять провайдеров при 429. Альтернативы: ручные адаптеры, пул ключей (нелегален). Решение: LiteLLM-прокси, ротация в конфиге. Последствия: код не знает о провайдерах.
- **ADR-002. Облако — основа, Ollama — фолбэк.** Альтернатива «локаль как основной мозг» требует отдельного железа под 7–14B.
- **ADR-003. hh.ru Open API вместо скрейпинга.** Последствия: меньше данных, зато без ToS-риска.
- **ADR-004. Скоуп — интеллект, а не отклики.** Целевая метрика — «5 вакансий с полным досье».
