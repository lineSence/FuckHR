## ADR-010. Источники данных

**Статус:** принято 16.09.2026.

**Решение.** Пять источников, разных по роли.

| Источник | Способ | Зачем |
|---|---|---|
| hh.ru | Open API: `/vacancies` + `/employers/{id}` + история публикаций | Основной поток вакансий + фактура для детектора |
| Habr Career | Порт адаптера из career-ops-ui | Вакансии + отзывы о работодателе |
| dreamjob.ru | Парсинг | Второй источник отзывов — без перекрёстной проверки один источник ненадёжен |
| Карьерные страницы | Гибрид: свой адаптер для целевых компаний, иначе Playwright + trafilatura + LLM | Вакансии, которых нет на джоббордах, и страницы «Команда» |
| Telegram-каналы | telethon, список каналов в конфиге | Ранний сигнал, часто до публикации на hh.ru |

**Почему глубокий hh.ru.** Без `/employers/{id}` и истории публикаций детерминированный слой ADR-009 наполовину пуст: флаг
«вакансия публиковалась 5 раз за 8 месяцев» — самый сильный сигнал текучки, и он строится только на истории.

**Следствия.**

- Историю публикаций нужно накапливать самим: каждый прогон пишет слепок `(вакансия, дата, статус)`. Система
  начинает давать полный сигнал не с первого запуска, а месяца через два.
- Карьерные страницы и Ollama конкурируют за ОЗУ: Playwright-этап выносится в отдельный шаг батча, до загрузки модели.
- Отзывы — мнения, а не факты. В карточке всегда указывается источник и число упоминаний, а не вывод LLM.

## ADR-011. Поиск для contact discovery: Tavily / Brave API

**Статус:** принято 16.09.2026.

**Решение.** Внешний поисковый API (Tavily либо Brave Search) через единый интерфейс `SearchProvider`,
чтобы провайдер менялся одной строкой конфига. Детерминированные источники (сайт компании, GitHub API,
Habr Career) опрашиваются **до** поиска; поиск — только для того, что не нашлось.

**Следствия.**

- Доступность и работоспособность из RU-сети проверяет владелец эмпирически (`[CORE-019]`).
- Ответы поиска кэшируются в SQLite по хэшу запроса: бесплатный тайр конечен.
- При недоступности поиска этап не падает, а возвращает меньше кандидатов (`[CORE-017]`).
- Запросы к внешнему поиску не содержат собранного досье — только имя компании и должность.

**Отвергнуто.** Локальный SearXNG — ещё один контейнер в 16 ГБ ОЗУ, где уже живут Ollama и Chromium.

## ADR-012. Система не отправляет письма

**Статус:** принято 16.09.2026. Отменяет ранее подразумевавшуюся отправку через SMTP.

**Решение.** Пайплайн заканчивается карточкой в Telegram: вакансия, флаги детектора, контакт, канал и готовый
черновик письма. **Отправляет человек сам, из своего почтового клиента.** В системе нет ни SMTP-клиента,
ни учётных данных почты, ни очереди отправки.

**Следствия.**

- Из стека уходят `aiosmtplib`, SPF/DKIM/DMARC, прогрев домена и вся тема доставляемости.
- `jinja2` остаётся: шаблон нужен для сборки черновика, а не для отправки.
- Проверка угаданного email сводится к формату и MX-записи домена (`email-validator`, `dnspython`).
  SMTP-проба убирается: она требует соединения с чужим сервером, которое больше ничему не служит.
- Факт отправки система знать не может — владелец отмечает его кнопкой в карточке. Дедуп по людям
  (`[OUT-007]`) теперь держится на дисциплине владельца, а не на логе отправки. Это известная слабость.
- Плюс: класс системы меняется с «автоматической рассылки» на «decision support». Спам технически невозможен,
  что снимает большую часть рисков из `wiki/rules/legal.md`.

## ADR-013. Профиль соискателя: резюме → YAML

**Статус:** принято 16.09.2026.

**Решение.** Резюме в PDF/DOCX разбирается один раз (`pdfplumber` / `python-docx` → LLM в профиле `local-only`)
в файл `profile.yaml`. Дальше источник истины — только YAML, он правится руками.

Содержимое: навыки с уровнем, стек, опыт в годах, желаемая вилка (net), гео и формат, стоп-слова
(технологии и типы компаний, которые отбрасываются до LLM), факты для писем (проекты, цифры, ссылки).

**Следствия.**

- Стоп-слова и вилка работают в детерминированном предфильтре до любого LLM-вызова (`[CORE-015]`).
- Блок «факты для писем» — единственный источник самоописания в черновике; выдумывать достижения LLM не имеет права.
- Резюме содержит ПД владельца, поэтому разбор идёт только локально (`[CORE-012]`).
