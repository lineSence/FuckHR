# ADR-014. Целевая платформа — Windows, без WSL и Docker

**Статус:** принято 16.09.2026. Заменяет упоминания systemd timers в ранних документах.

**Решение.** Система работает на Windows нативно: Python из winget, Ollama как служба Windows,
FreeLLMAPI как Node-процесс, планировщик — **Task Scheduler**. WSL и Docker не используются.

**Почему без WSL.** При 16 ГБ ОЗУ WSL2 забирает фиксированный кусок памяти и усложняет доступ
к GPU, а у Ollama есть родная сборка для Windows. Выгоды нет, издержки есть.

**Следствия.**

- `PYTHONUTF8=1` обязательна: иначе кириллица в описаниях вакансий ломается на cp1251.
- Пути только через `pathlib`; репозиторий — в ASCII-пути без пробелов.
- SQLite в WAL-режиме работает, но блокировки файлов жёстче: один пишущий процесс,
  открытый DB Browser во время прогона даст `database is locked`.
- `sqlite-vec` требует работающего `enable_load_extension` в сборке Python. Проверяется перед
  внедрением эмбеддингов; если не заработает — фолбэк на `numpy` и линейный поиск по памяти
  (на наших объёмах разница незаметна).
- Задача Task Scheduler запускается через `pythonw.exe` с галочкой «независимо от регистрации
  пользователя», иначе она молча не срабатывает при заблокированном экране.
- Спящий компьютер — основная причина пропущенных прогонов. Включить «Запустить задачу
  как можно скорее после пропуска запуска».
- APScheduler остаётся вариантом, если понадобится долгоживущий процесс (например, когда
  появится постоянно работающий Telegram-бот). Для батчей Task Scheduler надёжнее.
