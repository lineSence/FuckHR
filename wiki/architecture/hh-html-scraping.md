# Сбор вакансий hh.ru из HTML

## ADR-015: сбор с HTML-страниц вместо Open API

**Контекст.** ADR-010 закреплял hh.ru Open API как основной источник. На первом же боевом запуске (16.09.2026) `GET https://api.hh.ru/vacancies` ответил `403 Forbidden` на корректный запрос с валидным `User-Agent`. Причина не в конфиге: с апреля 2026 публичный поиск закрыт для неавторизованных клиентов, а токены выдаются преимущественно работодателям и партнёрам через модерацию. Проекту, вся идея которого — обход HR, такой доступ не выдадут.

**Решение.** Источник данных шага 1 — HTML-страницы `https://hh.ru/search/vacancy`. Реализация в `hh_html.py`, класс `HHHtmlClient` — drop-in замена `HHClient` для `run.py`.

**Почему именно так, а не селекторами по карточкам.** hh.ru рендерит выдачу из JSON, вшитого в страницу. Тот же JSON — те же поля, что в API: `compensation`, `workSchedule`, `area`, `snippet`. Поэтому модель `Vacancy`, скоринг, дедуп и схема БД остались без изменений, а ключ дедупа совпадает с тем, что давал API — история публикаций не обнулилась.

**Три уровня устойчивости.** Скрейпинг ломается от редизайна, поэтому жёстких путей в коде нет:

1. `extract_state` — четыре стратегии извлечения JSON (`HH-Lux-InitialState`, вариант с Redux, `window.__INITIAL_STATE__`, `__NEXT_DATA__`).
2. `find_vacancy_nodes` — обход состояния в ширину и поиск узлов по форме (`id` + `name` + одно из `compensation`/`company`/`area`), а не по пути вида `vacancySearchResult.vacancies`, который hh.ru переименовывал не раз.
3. `parse_cards_fallback` — если JSON не нашёлся совсем: из разметки берутся только ссылка и заголовок, остальное добирается со страницы вакансии. Скоринг беднее, но прогон не умирает.

**Диагностика.** `python probe_hh.py "python разработчик"` сохраняет `data/probe.html` и `data/probe_node.json`, показывает, какая стратегия сработала, сколько узлов найдено и какие у них ключи. При любой поломке сбора — сначала этот отчёт, потом правка маппинга в `node_to_vacancy`.

**Скромность сбора.** Один поток, пауза `HH_PAUSE` (по умолчанию 2 с) плюс случайная добавка до 1 с, backoff 5 → 10 → 20 с на 403/429, браузерные заголовки с `Accept-Language: ru-RU`. Страницы вакансий запрашиваются только для того, что прошло предфильтр; `--no-details` отключает их совсем.

**Капча.** `BlockedError` → код возврата 2 у `run.py`. Лечение по порядку: поднять `HH_PAUSE` до 4–6 с; пройти капчу в браузере и положить cookie в `HH_COOKIE`; снизить `max_pages` в `profile.yaml`; в крайнем случае `HH_PROXY` с RU-IP.

**Цена решения.** Сбор стал хрупким и медленным (секунды на запрос вместо десятков работающих RPS), меньше полей гарантировано, и это нарушение ToS hh.ru — осознанный операционный риск владельца (см. `wiki/rules/legal.md`). Взамен — работающий MVP без ожидания токена, который не выдадут.

**Путь назад.** `HHClient` в `hh.py` сохранён и принимает `user_agent` и `token` аргументами — переменных `HH_USER_AGENT` и `HH_TOKEN` в `.env` и на странице настроек больше нет, их никто не читал (20.09.2026). Если токен появится, возврат на API — одна строка в `run.py`. Анонимный 403 теперь бросает `PermissionError` с объяснением, а не сырой `HTTPStatusError`.

**Статус ADR-010.** Устарел в части «Open API как транспорт». Всё остальное (hh.ru как главный источник, слепки для истории публикаций) в силе.

## Что делать, если сбор сломался

| Симптом | Действие |
| --- | --- |
| `ЗАБЛОКИРОВАНО` или код возврата 2 | `HH_PAUSE=5`, затем свежий `HH_COOKIE` из браузера |
| `JSON состояния не найден` | `probe_hh.py`, потом новая запись в `STATE_PATTERNS` |
| вакансии есть, но без вилки/компании | сверить `data/probe_node.json` с ключами в `node_to_vacancy` |
| 0 вакансий без ошибок | проверить `queries` и `search_period` в `profile.yaml` |
