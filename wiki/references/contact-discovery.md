# Справочник: поиск нанимающего менеджера и рабочего контакта

Шаг пайплайна после финального скоринга. Вход: вакансия + досье компании.
Выход: 1–3 кандидата на контакт с ролью, каналом, источником и уровнем уверенности.

## 1. Определить нужную роль

По тексту вакансии восстанавливается, в какую команду идёт наём: отдел, продукт,
стек. Затем ищется человек, который этой командой руководит.

Приоритет: руководитель отдела/направления → тимлид → CTO/технический директор →
коллега на той же роли (может привести по реферальной программе).

## 2. Где искать людей (публичные источники)

| Источник | Что даёт | Замечания |
| --- | --- | --- |
| Сайт компании: «Команда», «О нас», «Блог» | ФИО, должность, иногда email | Самый чистый источник, нет ToS-проблем |
| Инженерный блог, changelog, доклады | авторы, тимлиды, стек команды | Хороший повод для письма |
| Habr (статьи и комментарии), Habr Career | авторы из компании, профили с контактами | Профиль часто содержит рабочий Telegram |
| GitHub (org members, коммиты в публичных репо) | ник, email из коммитов, роль по коду | Email из коммитов — публичный, но использовать аккуратно |
| Конференции: программы, слайды, YouTube | спикеры с должностями | Указывают отдел точнее вакансии |
| Telegram-чаты по стеку | люди, сами написавшие «мы нанимаем» | Лучший вход: контакт уже открыт |
| Реестры/карточка компании, hh.ru карточка | домен, общий email, структура | Для шаблона корпоративной почты |

LinkedIn как источник по РФ-рынку не используем: скрейпинг нарушает ToS
(`[LEG-002]`), а доступ нестабилен.

## 3. Как получить рабочий канал

1. Прямой email указан публично → использовать как есть.
2. Известен шаблон корпоративной почты + ФИО → вывести адрес, проверить
   валидатором один раз (`[OUT-008]`).
3. Указан рабочий Telegram/GitHub/личный сайт → писать туда.
4. Ничего нет → общий email компании с темой «для руководителя отдела X».
5. Всё равно ничего → отклик через обычную воронку, помечается в выдаче как
   «прямого контакта нет».

## 4. Что записывается в выдачу Telegram

```
Вакансия: <название>, <компания>
Скоринг: <балл> · HR-флаги: <список>
Контакт: <ФИО>, <должность> (уверенность: высокая/средняя/низкая)
Канал: <email | telegram | github>  ← источник: <url>
Повод: <факт из досье, на который опирается письмо>
Черновик письма: <5–7 строк>
[Отправил]  [Другой контакт]  [Пропустить]  [Не писать]
```

## 5. Структура первого письма

1. Одна строка: кто я и какую задачу их команды закрываю.
2. Один-два факта из досье/публикаций команды — доказательство, что письмо не рассылка.
3. Конкретное предложение: 20 минут разговора или ссылка на код/кейс.
4. Явное «если это не ваша зона — подскажите, к кому лучше».

Без: приветственных абзацев, слов «синергия», «увлечён вашей миссией», списка
всех навыков. Длина — до 1200 символов.

## 6. Риски

- **Юридика.** Рамка — `[LEG-001]`/`[CORE-013]`: только рабочие контакты и публичные
  данные. Никаких личных мобильных и личных соцсетей.
- **Репутация.** Массовая рассылка по сотрудникам одной компании превращает проект
  в спам-машину и закрывает компанию навсегда. Отсюда `[OUT-004]`.
- **Достоверность контакта.** Ошибочно угаданная роль хуже отсутствия контакта:
  письмо не тому человеку не пересылают. Низкая уверенность → показывать, но не
  предлагать отправку по умолчанию.
- **Неполнота источников.** По российским компаниям структура отделов публично
  раскрыта слабо; ожидаемое покрытие прямым контактом — меньшая часть вакансий.
  Это нормально: цель — 5 качественных входов, не 500.
