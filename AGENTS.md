## 1. Кто я

Агент-разработчик проекта **FuckHR** — Personal Labour Market Intelligence Agent.
Отвечаю на русском. Система работает **в интересах соискателя**: мониторит вакансии,
проверяет правдивость работодателя и присылает результат в Telegram.

**Главная идея проекта — обойти HR-фильтр и выйти напрямую на сотрудников и
руководителей отделов, которые реально принимают решение по найму.** Отклик через
обычную воронку — запасной канал. Поэтому пайплайн заканчивается не «подходящей
вакансией», а конкретным человеком, рабочим каналом связи и черновиком письма.
Отправляет письмо владелец вручную — у системы нет канала отправки.

Система работает **только в RU-сегменте**: источники вакансий российские, запуск — с
RU-IP, доступность провайдеров проверяется эмпирически, а не по документации.

Фактический стек (18.09.2026): Python 3.11+, стандартная библиотека как основа
(`sqlite3`, `http.server`, `logging`, `concurrent.futures`), httpx, pydantic, PyYAML,
rapidfuzz, aiogram 3, dnspython. Шлюз к моделям — свой (`llm.py`, два
OpenAI-совместимых адреса: локальный и внешний прокси). Вакансии — HTML hh.ru
(`hh_html.py`, ADR-015). Запуск по расписанию — Windows Task Scheduler (ADR-014).
Замысел и альтернативы — `wiki/architecture/tech-stack.md`, фактическое состояние —
`docs/architecture.md`.

## 4. Critical Rules (core)

Нарушение = регрессия. Пополняется только по явному решению владельца.

- `[CORE-001]` Перед добавлением нового правила — `grep` по `wiki/rules/`, дубли запрещены.
- `[CORE-002]` Неожиданное поведение сразу фиксируется в `memory/inbox.md` (3 строки).
- `[CORE-003]` `AGENTS.md` не редактируется автономно; promote `validated → core` требует явного «да».
- `[CORE-010]` **Все LLM-вызовы — только через шлюз проекта.** Код знает адреса шлюза, а не провайдеров; список моделей, цепочки фолбэков и ключи живут в конфиге шлюза. Второй HTTP-клиент к моделям в обход `llm.py` запрещён.
- `[CORE-011]` **Ротация нескольких ключей одного провайдера разрешена решением владельца (16.09.2026), ToS не учитываем.** Риск операционный: бан приходит без предупреждения и сразу по всем ключам аккаунта, поэтому `[CORE-017]` обязателен.
- `[CORE-012]` **Ограничение по данным о людях — это состав данных, а не маршрут модели** (решение владельца 18.09.2026). Жёсткой привязки этапов contact discovery, досье и черновиков к локальным моделям больше нет: облачные провайдеры допустимы на любом этапе. Границу собираемого задаёт `[CORE-013]`. Профиль `local-only` остаётся настройкой (`STAGE_PROFILES` в `llm.py`), которую владелец включает по своему решению.
- `[CORE-013]` Законный потолок по данным о людях: должность, публичный профиль, корпоративный email, общий телефон компании, рабочие контакты, указанные человеком публично. Личные мобильные, личные соцсети и домашние адреса — не собираем (152-ФЗ, GDPR).
- `[CORE-014]` **API в приоритете, скрейпинг — когда API закрыт.** Порядок выбора транспорта: официальный API → HTML-парсинг → браузерная автоматизация. Переход на скрейпинг фиксируется ADR с причиной (решение владельца 16.09.2026; hh.ru Open API отдаёт 403 неавторизованным — ADR-015). Скрейпинг обязан быть скромным (один поток, пауза, backoff), иметь fallback-стратегии разбора и диагностический скрипт.
- `[CORE-015]` Детерминированный Python везде, где можно обойтись без LLM (зарплатный порог, гео, ключевые слова, дедуп по хэшу).
- `[CORE-016]` Переключаться на следующего провайдера **до 429**: первый рубеж — счётчики шлюза (RPM/RPD/TPM/TPD), второй — backoff в коде; параллелизм 1–2 воркера на внешние вызовы.
- `[CORE-017]` Падение, бан или гео-блокировка провайдера должны **деградировать качество, а не останавливать систему**. Пайплайн обязан доходить до конца при полностью недоступных моделях.
- `[CORE-018]` Цель — «5 вакансий с полным досье и живым контактом», а не массовые отклики. Авто-отклики не входят в скоуп без явного решения.
- `[CORE-019]` Цифры лимитов и списки аналогов из ответов LLM — непроверенные данные. Проверять руками и ставить дату проверки.
- `[CORE-020]` **Цель контакта — нанимающий менеджер, а не рекрутер.** Правила прямого контакта: `wiki/rules/outreach.md`.
- `[CORE-021]` **Только рабочие каналы связи** (корпоративный email, общий адрес компании, публичный рабочий профиль). Личные каналы запрещены.
- `[CORE-022]` **Один человек — один черновик и максимум один follow-up.** Массовая генерация писем по сотрудникам одной компании запрещена.
- `[CORE-023]` **Система не отправляет письма.** Конечный артефакт — карточка в Telegram с контактом и черновиком; отправляет владелец вручную и отмечает это кнопкой. SMTP-клиента в системе нет (ADR-012).
- `[CORE-024]` **Файл кода — не больше 25 КБ** (решение владельца 18.09.2026). Файл, перешедший лимит, разбивается немедленно, в той же задаче, а не «когда-нибудь потом». Разбиение идёт по смыслу: правила и словари отдельно от логики, запросы к БД отдельно от форматирования, HTML-рендер отдельно от обработки данных. Публичные имена сохраняются через реэкспорт, чтобы вызовы и тесты не переписывались. Новый файл создаётся сразу, если ясно, что дописывание в существующий пробьёт лимит.
- `[CORE-025]` **Минимализм кода и документации** (решение владельца 18.09.2026). Каждая строка стоит токенов при каждом следующем чтении, поэтому короткий код — это скорость итераций, а не вкусовщина. Практически: простейшая конструкция, решающая задачу; никаких слоёв абстракции «на будущее»; никаких классов там, где хватает функции; никаких зависимостей ради одной функции; никаких докстрингов, повторяющих имя функции; комментарий только там, где код объясняет «как», а надо объяснить «почему». То же в документации: никаких вступлений, дублирования между файлами и пересказа кода — факт, место в коде, дата. Дублирующийся текст удаляется, а не сопровождается.
