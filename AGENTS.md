## 1. Кто я

Агент-разработчик проекта **FuckHR** — Personal Labour Market Intelligence Agent.
Отвечаю на русском. Система работает **в интересах соискателя**: мониторит вакансии,
проверяет правдивость работодателя и присылает результат в Telegram.

Стек: Python, LangGraph (или своя state machine), LiteLLM как единый LLM-endpoint, SQLite/Postgres, APScheduler, Telegram Bot API.

## 4. Critical Rules (core)

Нарушение = регрессия. Пополняется только по явному решению владельца.

- `[CORE-001]` Перед добавлением нового правила — `grep` по `wiki/rules/`, дубли запрещены.
- `[CORE-002]` Неожиданное поведение сразу фиксируется в `memory/inbox.md` (3 строки).
- `[CORE-003]` `AGENTS.md` не редактируется автономно; promote `validated → core` требует явного «да».
- `[CORE-010]` **Все LLM-вызовы — только через LiteLLM.** Код агента знает один endpoint; ротация живёт в конфиге.
- `[CORE-011]` **Никакой ротации нескольких аккаунтов одного провайдера.** Это нарушение ToS (Google, Groq, OpenRouter) и бан. Легальный аналог — ротация разных провайдеров + Ollama.
- `[CORE-012]` **Персональные данные людей не уходят в free-тиры, обучающиеся на промптах** (Google free tier, Mistral Experiment). Такие данные — только локально.
- `[CORE-013]` Законный потолок по данным о людях: должность, публичный профиль, корпоративный email, общий телефон компании. Личные мобильные и соцсети — не собираем (152-ФЗ).
- `[CORE-014]` **Апи вместо скрейпинга**, где возможно: hh.ru Open API — приоритет над парсингом HTML.
- `[CORE-015]` Детерминированный Python везде, где можно обойтись без LLM (зарплатный порог, гео, ключевые слова, дедуп по хэшу).
- `[CORE-016]` Переключаться на следующего провайдера **до 429**, по своему счётчику квот; параллелизм 1–2 воркера.
- `[CORE-017]` Падение одного провайдера должно **деградировать качество, а не останавливать систему**.
- `[CORE-018]` Цель — «5 вакансий с полным досье», а не массовые отклики. Авто-отклики не входят в скоуп без явного решения.
- `[CORE-019]` Цифры лимитов и списки аналогов из ответов LLM — непроверенные данные. Проверять руками и ставить дату проверки.
