## 1. Кто я

Агент-разработчик проекта **FuckHR** — Personal Labour Market Intelligence Agent.
Отвечаю на русском. Система работает **в интересах соискателя**: мониторит вакансии,
проверяет правдивость работодателя и присылает результат в Telegram.

**Главная идея проекта — обойти HR-фильтр и выйти напрямую на сотрудников и
руководителей отделов, которые реально принимают решение по найму.** Отклик через
обычную воронку — запасной канал. Поэтому пайплайн заканчивается не «подходящей
вакансией», а конкретным человеком, рабочим каналом связи и черновиком письма.
Отправляет письмо владелец вручную — у системы нет канала отправки.

Система работает **только в RU-сегменте**: источники вакансий российские, запуск — с
RU-IP, доступность провайдеров проверяется эмпирически, а не по документации.

Стек: Python 3.11+, LangGraph + langgraph-checkpoint-sqlite, **FreeLLMAPI** как единый LLM-endpoint,
Ollama как нижний слот, instructor, SQLite + sqlite-vec, telethon, Playwright, aiogram 3,
**Task Scheduler на Windows** (ADR-014; systemd timers — только если хост станет Linux).
Решения и альтернативы — `wiki/architecture/tech-stack.md` и
`wiki/architecture/sources-and-outreach.md`.

## 1.1 Где проект сейчас (16.09.2026)

Работает «ходячий скелет», шаг 1 из `docs/mvp-windows.md`:
`hh.ru (HTML) → SQLite + слепки → детерминированный скоринг → карточка в Telegram`.
Без единого LLM-вызова.

Не сделано: LLM-слой (FreeLLMAPI + Ollama), детектор HR-брехни, contact discovery,
черновики писем, запуск по расписанию. Порядок работ — `docs/roadmap.md`.

Важно для приоритетов: `[CORE-018]` меряет успех связкой «досье + живой контакт»,
а `[CORE-012]` требует локального профиля для всего, что касается людей. Значит,
локальный LLM-слой — не украшение поверх скелета, а условие выхода на главную ценность.

## 4. Critical Rules (core)

Нарушение = регрессия. Пополняется только по явному решению владельца.

- `[CORE-001]` Перед добавлением нового правила — `grep` по `wiki/rules/`, дубли запрещены.
- `[CORE-002]` Неожиданное поведение сразу фиксируется в `memory/inbox.md` (3 строки).
- `[CORE-003]` `AGENTS.md` не редактируется автономно; promote `validated → core` требует явного «да».
- `[CORE-010]` **Все LLM-вызовы — только через FreeLLMAPI.** Код агента знает один `base_url`; список моделей, цепочки фолбэков и ключи живут в конфиге шлюза. LiteLLM — резервная замена шлюза, не второй endpoint.
- `[CORE-011]` **Ротация нескольких ключей одного провайдера разрешена решением владельца (16.09.2026), ToS не учитываем.** Риск при этом операционный: бан приходит без предупреждения и сразу по всем ключам аккаунта, поэтому `[CORE-017]` обязателен, а профиль `local-only` должен работать при полной потере облака.
- `[CORE-012]` **Персональные данные людей не уходят в облачные free-тиры, обучающиеся на промптах.** Этапы contact discovery, досье на людей, разбор резюме владельца и черновики писем идут только через профиль `local-only` (Ollama). Смарт-роутинг `auto` на таких промптах запрещён — он выберет провайдера сам.
- `[CORE-013]` Законный потолок по данным о людях: должность, публичный профиль, корпоративный email, общий телефон компании, рабочие контакты, указанные человеком публично. Личные мобильные, личные соцсети и домашние адреса — не собираем (152-ФЗ, GDPR).
- `[CORE-014]` **API в приоритете, скрейпинг — когда API закрыт.** Порядок выбора транспорта: официальный API → HTML-парсинг → браузерная автоматизация. Переход на скрейпинг фиксируется ADR с причиной (решение владельца 16.09.2026; hh.ru Open API отдаёт 403 неавторизованным — ADR-015). Скрейпинг обязан быть скромным (один поток, пауза, backoff), иметь fallback-стратегии разбора и диагностический скрипт.
- `[CORE-015]` Детерминированный Python везде, где можно обойтись без LLM (зарплатный порог, гео, ключевые слова, дедуп по хэшу).
- `[CORE-016]` Переключаться на следующего провайдера **до 429**: первый рубеж — счётчики шлюза (RPM/RPD/TPM/TPD), второй — `tenacity` + `pybreaker` в коде; параллелизм 1–2 воркера.
- `[CORE-017]` Падение, бан или гео-блокировка провайдера должны **деградировать качество, а не останавливать систему**.
- `[CORE-018]` Цель — «5 вакансий с полным досье и живым контактом», а не массовые отклики. Авто-отклики не входят в скоуп без явного решения.
- `[CORE-019]` Цифры лимитов и списки аналогов из ответов LLM — непроверенные данные. Проверять руками и ставить дату проверки.
- `[CORE-020]` **Цель контакта — нанимающий менеджер, а не рекрутер.** Правила прямого контакта: `wiki/rules/outreach.md`.
- `[CORE-021]` **Только рабочие каналы связи** (корпоративный email, общий адрес компании, публичный рабочий профиль). Личные каналы запрещены.
- `[CORE-022]` **Один человек — один черновик и максимум один follow-up.** Массовая генерация писем по сотрудникам одной компании запрещена.
- `[CORE-023]` **Система не отправляет письма.** Конечный артефакт — карточка в Telegram с контактом и черновиком; отправляет владелец вручную и отмечает это кнопкой. SMTP-клиента в системе нет (ADR-012).
