# Синтетический датасет для файнтюна локальной модели

```powershell
.venv\Scripts\python training/make_dataset.py        # data/train/{train,val}.jsonl
```

819 примеров на 11 этапов пайплайна, формат `{"stage": ..., "conversations":
[system, user, assistant]}` — то, что Unsloth ждёт в `standardize_sharegpt`.
Ответы финальные, без рассуждений: на 8 ГБ VRAM thinking-режим стоит секунд.

Промпты не переписаны руками. Сборщик подставляет в функции пайплайна
шлюз-перехватчик и забирает те самые сообщения, которые уходят в модель в
проде — вместе с обёрткой `injection.safe`. Тот же прогон служит проверкой:
эталон возвращается в функцию, и пример попадает в файл, только если пайплайн
его принял (цитата дословная, число не выдумано, номер из списка).

Данные выдуманы целиком: компаний, вакансий и людей из них не существует
[CORE-013]. Файл уезжает в Colab, то есть в облако, поэтому живых ФИО и
контактов в нём быть не должно — при пополнении датасета это правило главнее
реалистичности.

С кейсами `bench_cases` и `bench_hard` пересечений нет: иначе балл сравнения
моделей превратится в проверку зубрёжки. Проверять обучение — бенчем на
локальном маршруте (`bench.py --route local`), до и после.

Ловушки и отказы — 90 примеров из 819: условий в тексте нет, проверяемых
утверждений нет, технического руководителя в списке нет, данных для выводов
мало. Без них модель учится всегда что-нибудь отвечать [CORE-019].

Этапы с персональными данными (`contacts`, `dossier`, `draft`, `review_fake`)
в датасете есть, но только на выдуманных людях: обучение идёт форме ответа,
а не содержанию [CORE-012].
