# Как участвовать

## Код

- Ветки: `feat/*`, `fix/*`, `docs/*` от `main`.
- Коммиты: Conventional Commits.
- PR: что сделано, что проверено, какие файлы документации затронуты.
- Перед PR: `ruff check .` и `python -m pytest -q` — то же гоняет CI (`.github/workflows/ci.yml`).
- Новый модуль — в пакет своего слоя (`docs/architecture.md`, «Пакеты и слои»). Импорт только
  своего слоя и ниже, без циклов; нарушение ловит `tests/test_architecture.py`. Новый пакет —
  строка в `LAYERS` этого теста.
- Файл делится, когда в нём две несвязанные ответственности, а не когда он вырос (`[CORE-024]`).
- Новая страница интерфейса — функция и строка в таблице `GET`/`POST` в `fuckhr/web/webui.py`.
  Новый этап прогона — функция над `Run` и место в `COLLECT` или `AFTER` в `fuckhr/pipeline/run.py`.

## Документация

1. Новый факт о проекте → сначала `memory/inbox.md` (если это наблюдение) или сразу `wiki/`, если факт подтверждён.
2. Новый файл в `wiki/` → обязательно добавить в `wiki/_routing.md` (keywords) и `wiki/_index.md` (описание одной строкой).
3. Правило получает уникальный ID-тег `[TAG-NNN]`. Перед добавлением — `grep`, чтобы не дублировать.
4. Один факт — одно место. Как устроен код сейчас — `docs/`; замысел и причины решений —
   `wiki/architecture/`, со ссылкой на `docs/` за текущим состоянием. README — только что это,
   как запустить и где читать дальше.
5. `AGENTS.md` правим только осознанно: это core-уровень, изменение = изменение конституции проекта.

- [ ] Новое правило → уникальный тег, дублей нет
