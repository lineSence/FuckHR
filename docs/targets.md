# Цели: изучить компанию целиком

Что делает код сейчас. Решение и обоснование — ADR-025
(`wiki/architecture/targets.md`).

## Как добавить

Раздел «Цели» → поле ввода. Принимается:

| Что вписал | Что происходит |
|---|---|
| название | показываются кандидаты с hh.ru, выбираешь нужного |
| `hh.ru/employer/1455` | компания добавляется сразу |
| `hh.ru/vacancy/777` | берётся работодатель этой вакансии |
| ИНН (10 или 12 цифр) | цель заводится без работодателя hh.ru: для реестров этого хватит, для вакансий — нет |

Компанию, найденную прогоном, переносит в цели звёздочка «★ В цели» на странице
её досье.

## Кнопка «Собрать все данные»

Одна кнопка у цели запускает все три шага подряд одной задачей:

| Шаг | Что делает | Чем стоит |
|---|---|---|
| вакансии | все открытые вакансии компании на hh.ru | обход выдачи по `employer_id` |
| отзывы и оценка | досье по отзывам + общая оценка работодателя | запросы к поиску, как в прогоне |
| глубокий ресёрч | реестр, суды, долги, банкротство, новости | бюджет времени `DEEP_SECONDS` |

Почему одна, а не три: задача в интерфейсе идёт ровно одна (`jobs.py`), и три
кнопки означали три ожидания подряд. Цена шагов от этого не исчезла, поэтому
запуск остался ручным [CORE-016]: не нажал — ничего не тратится. Лог виден на
странице «Запуск», шаги помечены `[1/3]`, `[2/3]`, `[3/3]` — по ним же рисуется
полоска прогресса.

Шаг, который сейчас невозможен, пропускается строкой в логе, остальные
доезжают:

- у цели нет работодателя на hh.ru (цель по ИНН) — пропускаются вакансии;
- `DEEP_ENABLED=0` — пропускается глубокий ресёрч.

Перезапустить один упавший шаг можно из терминала:
`python target_scan.py --target 3 --step reviews` (шаги: `vacancies`, `reviews`,
`research`, `all`).

## Порядок и фильтр списка

Над списком две строки кнопок. Выбранное подсвечено.

| Порядок | Как сортирует |
|---|---|
| по добавлению | свежие цели сверху (умолчание) |
| по названию | алфавит, без оглядки на регистр |
| по новым | больше всего новых вакансий сверху |
| по вакансиям | больше всего вакансий сверху |
| по последнему сбору | кого смотрели позже всех — сверху |

| Показать | Кто остаётся в списке |
|---|---|
| все | все цели (умолчание) |
| со слежением | те, у кого включено «Следить» |
| с новыми | у кого есть непросмотренные вакансии |
| без работодателя | цели по ИНН и те, где компания с hh.ru ещё не выбрана |

Правила те же, что у фильтров вакансий (`docs/filters.md`): из браузера приходит
только имя, оно ищется в словаре `targets.py`, чужое молча заменяется
умолчанием [CORE-017]. Второй стрелки сортировки нет [CORE-025].

## Что видно в списке

Каждая цель — сворачиваемый блок. Закрытый показывает название и строку вроде
«вакансий 12 · новых 3 · следим · смотрели 2026-09-20». Открытый — кнопки
(«Открыть», «Собрать все данные», «Следить», «Убрать») и вакансии цели прямо
в списке. На странице самой цели таблица вакансий тоже сворачивается, но
открыта сразу.

## Слежение

Кнопка «Следить» у цели. В прогоне такие цели обходятся **не чаще раза в
сутки**; новые вакансии помечаются словом «новая» и перестают быть новыми,
когда ты открыл цель.

## Что видно у цели

Все вакансии компании, а не только прошедшие порог: цель выбрана руками. Скор
рядом — справочно, по лучшему профилю. Письмо пишется обычным путём, от
вакансии: правило «одно письмо на компанию» [OUT-004] цель не отменяет.

## Известные ограничения

- Описания вакансий шагом не догружаются: текст подтянется на странице вакансии.
- ИНН вводится, но сам по себе работодателя на hh.ru не находит.
- Список кандидатов и выбранный порядок/фильтр живут в памяти процесса: после
  перезапуска интерфейса снова «по добавлению» и «все», а кандидатов ищи заново.
- Разбор страницы работодателя ломается вместе с редизайном hh.ru — тогда
  кандидатов просто нет, ошибки не будет.
- Уведомлений в Telegram о новых вакансиях цели пока нет: только пометка в
  разделе и строка в логе прогона.
