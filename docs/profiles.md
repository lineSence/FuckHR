# Несколько профилей поиска

Что делает код сейчас. Решение и обоснование — ADR-023
(`wiki/architecture/profiles.md`).

## Как включить

1. Скопировать `profiles_example/` в `profiles/` и поправить файлы под себя.
   Имя файла — идентификатор профиля (`python_backend.yaml` → `python_backend`).
2. В настройках, поле «Файл или каталог профилей» (`RUN_PROFILE`), указать
   каталог `profiles` вместо `profile.yaml`.

Один файл продолжает работать: это список из одного профиля, и прогон ведёт себя
ровно как раньше.

## Что считается

```
profiles.load_all      файл или каталог → список профилей
profiles.collect_all   обход hh.ru по каждому профилю, склейка по ключу вакансии
profiles.score_all     вердикт каждого профиля, который забрал вакансию
profiles.passed        профили, где вакансия перешла СВОЙ порог
db.save_matches        связи в vacancy_profiles
```

| Общее для всех профилей | Своё у каждого профиля |
|---|---|
| вакансии, слепки, дедуп | запросы к hh.ru и предфильтр |
| досье, оценка работодателя, рынок | скор и причины |
| контакты, блоки, follow-up | порог `min_score` |
| факты о владельце | — |

В записи вакансии (`vacancies.score`) лежит **лучший** балл: по нему работают
сортировки, порог карточек и всё написанное до профилей. Балл каждого профиля —
в `vacancy_profiles`, потому что критерии у профилей разные.

В досье и в поиск контактов вакансия попадает, если перешла порог **своего**
профиля. Общий лучший балл против чужого `min_score` не сравнивается: иначе
вакансия проходила бы по порогу соседа.

## Известные ограничения

- `limit` прогона действует **на каждый профиль**: это ограничение обхода hh.ru,
  а обходов теперь столько, сколько профилей.
- Профили обходятся по очереди. Параллельный обход — B-09, отдельное решение.
- В карточке Telegram профиль пока не подписан: чат один, подпись — следующий шаг.
- Фильтра по профилю в интерфейсе пока нет; связи уже пишутся, страница их ещё не
  показывает.
- Существующая база не мигрируется: решение владельца — можно начать с чистой.
