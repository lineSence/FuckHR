# Сравнение моделей: какая куда годится

Профили `auto:fast` / `auto:smart` / `auto:long` / `local-only` отвечают, какого
класса модель нужна этапу [LLM-003]. Какая именно модель за этим профилем стоит —
вопрос к прогону: по-русски и на выдумки модели ведут себя очень по-разному.

```powershell
.venv\Scripts\python bench.py --models qwen2.5-7b,gpt-4o-mini
.venv\Scripts\python bench.py --models llama3.1 --route local
.venv\Scripts\python bench.py --models a,b --stages extract,draft --repeat 3 --json data/bench.json
```

То же самое есть в интерфейсе: страница «Модель» → «Сравнение моделей». Модели
выбираются галочками (список приходит по ссылке «Спросить список моделей») или
вписываются руками, рядом — этапы и число прогонов. После кнопки «Сравнить»
страница остаётся на месте и обновляется сама: видно полоску «кейс 7 из 24» и
последнюю строку прогона, а по окончании — таблицу баллов, строку победителей и
разбор кейсов; сырой лог остаётся по ссылке «полный лог». Имена моделей из формы
проходят проверку (`ui_forms.bench_models`): в командную строку не попадает
ничего, кроме имён.

Команда ходит в сеть и тратит вызовы: это не часть `pytest`. Кэш ответов выключен
намеренно — сравниваем модели, а не попадания в кэш.

## Как считается балл

Оценка детерминированная и совпадает с тем, что пайплайн и так требует от ответа:
цитата дословно из текста, никаких чисел сверх исходных, адресат из списка
[CORE-015], [CORE-019]. Красноречие не оценивается никак.

| Этап | Кейс | Что считается успехом |
| --- | --- | --- |
| `intake` | слова о себе | из свободного текста заполнены запросы, зарплата и формат, ничего не дорисовано |
| `intake` | ничего не сказано (ловушка) | критерии **не** выведены из общих слов, заданы вопросы |
| `extract` | гибрид и вилка | найдены поля `format` и `salary` с дословными цитатами |
| `extract` | вилки нет (ловушка) | условия разобраны и сумма **не** дорисована: в поле `salary` нет числа, которого нет в тексте. Само поле `salary` с дословной цитатой («обсуждаем на собеседовании») — правильный разбор |
| `hr_filter` | обещания вакансии | найдены минимум два обещания дословными цитатами |
| `hr_filter` | обещать нечего (ловушка) | в сухом тексте обещаний **не** найдено |
| `company` | справка по сниппетам | 3–5 строк, ни одной цифры сверх сниппетов, без маркетинга |
| `contacts` | выбрать CTO | выбран технический руководитель, а не кадровик |
| `contacts` | кадровик первым (ловушка) | выбран тимлид, хотя HR стоит первым в списке |
| `dossier` | сводка по отзывам | 3–6 строк по текстам отзывов, без новых цифр |
| `draft` | переписать письмо | текст изменён и прошёл проверки `polish_draft` (не откат) |
| `resume_section` | оформить ответ | черновик секции принят: ни одного числа сверх ответа владельца, без раздува |
| `resume_tailor` | отобрать блоки | первым идёт релевантный опыт, номера только из списка |

Треть набора — ловушки. Модель, которая пишет красиво, но дорисовывает вилку,
для этого проекта хуже скучной и точной.

## Отчёт

Прогон пишет `data/bench/last.json` (путь меняется флагом `--json`): параметры
запуска и все строки. Страница «Модель» рисует отчёт из этого файла — второй
копии в базе нет [CORE-025].

На выходе — таблица «этап × модель» со средним баллом, строка лучшего балла по
каждому этапу и разбор по кейсам с причиной: «выдумала поле», «откат к
черновику», «маркетинг».

Под таблицей — блок «Подставить в настройки»: `bench.recommend` выбирает модель
**на каждый этап** — сначала по баллу, а при разнице меньше 0.05 по скорости
ответа: на шести кейсах две сотых балла ничего не значат, а секунды на каждом
вызове значат [CORE-016]. Отмеченные этапы записываются в `.env`
(`LLM_STAGE_MODEL_EXTRACT` и соседи), руками переносить в «Настройки» больше не
нужно. Галочка снята там, где нужная модель уже стоит. Ключ из браузера
сверяется с закрытым списком, имя модели — с `bench_models`.

Модель этапа сильнее модели профиля: профиль отвечает, какого класса модель
нужна, а победитель у одноклассников разный — на `extract` одна модель, на
`draft` другая. Пустой `LLM_STAGE_MODEL_*` возвращает этап на модель профиля.
Откуда взялось имя, видно в колонке «Имя из» на странице «Модель», в
`check_llm.py` и в логе прогона. Ручная правка — группа «Модель по этапам» на
странице «Настройки».

В CLI тот же выбор печатается блоком «Подставить в настройки» после таблицы.

## Личные данные

Кейсы выдуманы целиком, ФИО и контактов в них нет, поэтому бенчмарк гоняет и
персональные этапы (`contacts`, `draft`) через прокси [CORE-012]. На реальных
данных это по-прежнему требует явного `LLM_PERSONAL_VIA_PROXY=1`.
