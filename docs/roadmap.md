# Roadmap

Порядок продиктован `[CORE-018]` (цель — досье + живой контакт) и `[CORE-012]`
(всё, что касается людей, считается только локально). Поэтому локальный LLM-слой идёт
раньше детектора брехни: без него главный этап проекта запускать нельзя.

## Шаг 0. Проверки до кода

- [x] Проверить на GitHub реальность проектов-аналогов
- [x] Выбрать транспорт для hh.ru: Open API отдаёт 403 неавторизованным → HTML (ADR-015)
- [ ] Сверить руками актуальные лимиты Groq, Gemini, Cerebras, OpenRouter (`wiki/workflows/quota-audit.md`)
- [ ] Проверить доступность Gemini AI Studio из своей сети; если нет — Groq становится основным мозгом
- [ ] Определить железо под локальный фолбэк и выбрать модель 8–14B с tool calling
- [ ] Зафиксировать законный потолок по данным о людях (уже в `wiki/rules/legal.md`, требует подтверждения)
- [ ] Уточнить скоуп OSINT по руководителям: нужен ли поиск точки входа в обход HR

## Шаг 2. Надёжная история публикаций (ближайший)

Без этого детектор брехни математически не заработает: его главный сигнал — история
(ADR-009, ADR-010), а её нельзя восстановить задним числом.

- [ ] Запуск по расписанию через Task Scheduler (ADR-014), два раза в сутки
- [ ] Отметка `is_active = 0` для вакансий, пропавших из выдачи
- [ ] Нормализация `published_at` из HTML: проверить, что поле не пустое, иначе `republish_count` всегда 0
- [ ] Канарейка: 0 вакансий, `BlockedError` или пустые описания у >30% карточек → сообщение в Telegram
- [ ] Сохранение сырого HTML последнего неудачного прогона для починки парсера
- [ ] Отчёт `stats` в конце прогона: вакансий, слепков, отправлено

## Шаг 3. LLM-слой, профиль local-only

- [ ] FreeLLMAPI как единственный `base_url` (`[CORE-010]`)
- [ ] Ollama, `qwen3:8b`, профиль `local-only` для всего, что касается людей (`[CORE-012]`)
- [ ] `instructor`: извлечение полей из описания в структурированный JSON
- [ ] Кэш ответов по хэшу промпта
- [ ] Счётчики квот в шлюзе, переключение провайдера до 429 (`[CORE-016]`)

## Шаг 4. Contact discovery — главная ценность

- [ ] От работодателя (`company_id`) к сайту компании и публичным рабочим профилям
- [ ] Поиск нанимающего менеджера, а не рекрутера (`[CORE-020]`)
- [ ] Валидация рабочего канала связи (`[CORE-021]`), потолок по данным (`[CORE-013]`)
- [ ] Черновик письма: один человек — один черновик и максимум один follow-up (`[CORE-022]`)
- [ ] Карточка с контактом и черновиком + кнопка «отправил» (`[CORE-023]`)
