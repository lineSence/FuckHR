# Архитектура

Описание того, что работает сейчас. Нормативные решения и их обоснование — в `wiki/architecture/`.
Где решение на практике заменено другим, это отмечено прямо здесь: ADR остаются историей выбора,
а не описанием кода.

## Контур

Один пользователь, одна машина на Windows (`C:\dev\fuckhr`), всё в RU-сегменте. Внешние адреса — только
hh.ru, сайты отзывов, свой SearXNG, Telegram и адреса моделей. Никакой облачной инфраструктуры и
никакого AI-CLI внутри рантайма.

## Цепочка одного прогона (`run.py`)

```
hh.ru (HTML поиска, ADR-015)
  → предфильтр и скоринг (score.py, без модели)
  → страница вакансии (hh_html.py) при включённых деталях
  → слепок в историю (db.vacancy_snapshots, ADR-010)
  → условия из описания (llm_tasks.extract_conditions, этап extract)
  → детектор утверждений (detector.py + detector_llm.py, ADR-009)
  → досье на компании, прошедшие порог (dossier.py, в несколько потоков)
  → карточки в Telegram (bot.py)
  → канарейка, если прогон сам сломался (canary.py)
```

Писем в прогоне нет и не будет: контакты и черновики готовит `outreach.py` по явной команде владельца
(`[OUT-006]`, ADR-012, `[CORE-023]`).

## Как собирается досье

```
dossier.build(company)
  → websearch.SearchProvider   поиск по сайтам отзывов (SearXNG / Tavily / Brave), кэш search_cache
  → reviewpage.PageFetcher     чтение самих страниц отзывов, кэш page_cache на 30 дней
  → dossier.find_patterns      словарь маркеров + учёт отрицаний, без модели
  → dossier.summarize          сводка словами (этап company), необязательная
  → company_dossier / company_reviews
```

Ключевое свойство: флаги и уровень риска считает Python по словарю `PATTERN_RULES`, модель только
пересказывает (`[CORE-015]`). Поэтому досье воспроизводимо и объяснимо: в интерфейсе видно, какая
фраза в каком отзыве дала флаг.

## Модули

| Файл | Ответственность |
|---|---|
| `run.py` | один прогон целиком, логирование, счётчики прогресса |
| `hh_html.py`, `hh.py` | поиск и карточка вакансии из HTML, дампы сбоев в `data/failures` |
| `score.py`, `profile.yaml` | предфильтр и скоринг по профилю соискателя |
| `db.py` | вакансии, слепки, перепубликации, очередь карточек |
| `detector.py`, `detector_llm.py` | проверяемые утверждения вакансии и вердикты по истории |
| `conditions.py` | условия работы, извлечённые из описания |
| `websearch.py` | внешний поиск с кэшем и потолком запросов |
| `reviewpage.py` | загрузка и очистка страниц отзывов, кэш страниц |
| `dossier.py` | досье: отзывы, маркеры, риск, сводка |
| `contacts.py`, `outreach.py` | поиск рабочих контактов и черновики писем |
| `llm.py`, `llm_tasks.py`, `check_llm.py` | шлюз к моделям, задачи этапов, диагностика |
| `bot.py` | карточки и тревоги в Telegram |
| `canary.py` | тревога, когда прогон сломался, с суточным cooldown |
| `maintenance.py` | очистка кэшей и данных по целям, с отметкой необратимых |
| `webui.py`, `jobs.py`, `ui_*.py` | локальный интерфейс и запуск задач подпроцессами |
| `settings.py` | чтение и запись `.env` как единственного источника настроек |

## Хранилище

Один файл SQLite (`data/fuckhr.sqlite3`). Таблицы: `vacancies`, `vacancy_snapshots`, `vacancy_conditions`,
`hr_signals`, `company_dossier`, `company_reviews`, `contacts`, `search_cache`, `page_cache`, `llm_cache`.

Векторов нет: `sqlite-vec` из ADR-008 не подключён, семантический дедуп не нужен на текущих объёмах.
Невосстановимы только `vacancy_snapshots` — hh.ru не расскажет задним числом, что вакансия висела в апреле
и исчезла в мае (`maintenance.py` помечает эту цель как опасную).

## Модели

Шлюз `llm.py` знает два адреса: локальный (`LLM_BASE_URL`) и необязательный внешний прокси
(`LLM_PROXY_BASE_URL`). Этап выбирает профиль (`STAGE_PROFILES`), профиль выбирает маршрут.
Этапы `contacts`, `dossier`, `draft` работают с данными о живых людях и остаются на локальном адресе,
пока владелец не выставит `LLM_PERSONAL_VIA_PROXY=1` (`[CORE-012]`).

Кэш ответов по хэшу промпта включён всегда (`[LLM-006]`), потолок вызовов за прогон — `LLM_MAX_CALLS`.
Любая ошибка модели возвращает `None`, а не исключение (`[CORE-017]`, `[LLM-009]`).

Оркестратора нет: `run.py` — обычная последовательность вызовов. LangGraph из ADR-007 не внедрён,
потому что паузы на подтверждение внутри прогона не появилось: подтверждение живёт в `outreach.py`
и в интерфейсе.

## Запуск

Интерфейс и прогон запускаются отдельно. Планировщик Windows запускает `run.py` через `pythonw.exe`
(ADR-014), интерфейс можно держать в фоне тем же способом. Задачи из интерфейса идут подпроцессами:
упавший сбор не уносит с собой страницу, из которой смотришь, почему он упал.

## Границы

- Западные ATS (Greenhouse, Ashby, Lever) и LinkedIn не поддерживаются.
- Интерфейс слушает только `127.0.0.1`, без авторизации и CSRF-защиты: наружу его выставлять нельзя.
- По данным о людях — только рабочие каналы, никаких личных мобильных, личных соцсетей и покупных баз
  (`[CORE-013]`, `wiki/rules/legal.md`).

## Критерий готовности

Пять вакансий с полным досье за прогон (`[CORE-018]`). Досье считается полным, когда у флагов есть
цитаты из прочитанных отзывов, а не только из заголовков выдачи.
