# Laya: решатель вместо генерации на двух этапах

Что это. [Laya](https://github.com/NandhaKishorM/laya) — энкодер (ModernBERT-large
421M или mmBERT-base 322M на 100+ языков), который отвечает на типизированные
вопросы за один прямой проход: `choice` (метка), `score` (уровень), `noul`
(вероятность «да»). Текст не генерируется, парсить нечего.

Зачем проекту. Два этапа не пишут текст, а выносят решение: `review_fake`
(«заказной отзыв?») и `ai_text` («сгенерировано?»). Сейчас на них ходит
генеративная модель, ответ приходится разбирать и проверять цитатой.

Чего Laya **не** делает: спанов она не возвращает, поэтому GLiNER на этапе
`extract` не заменяет — там нужна дословная цитата из текста.

## Сравнительный прогон

```
python laya_bench.py                                   # только Laya
python laya_bench.py --sweep 0.5,0.7,0.9,0.97          # один прогон, разные пороги
python laya_bench.py --model qwen3:8b --route local    # Laya против модели
python laya_bench.py --stages review_fake --cases my.json --threshold 0.6
```

`--sweep` зовёт модель один раз на текст и потом считает баллы для каждого
порога: перебор порогов не стоит ещё десяти прогонов. Там же проверяется, не
отвечает ли решатель по позиции варианта (ниже). Колонка «с/текст» в `--sweep`
нулевая: время уходит в общий замер до таблицы.

Вторая сторона (`--model`) живёт в пайплайне, поэтому окружению нужны
зависимости проекта: `python -m pip install -r requirements.txt` в то же
окружение, где стоит Laya.

Кейсы — те же, что у `bench.py` (`bench_cases.py`, `bench_hard.py`), плюс свои
из JSON: `[{"name": "мои отзывы", "texts": ["..."], "ad": [1], "level": 3}]`.

Балл считается правилом этих этапов: **ложное срабатывание обнуляет кейс,
пропуск половинит** — молчать на живом тексте важнее, чем поймать рекламу.
Вес уровня сложности тот же, что в `bench_metrics` (1/2/3). В отчёте:

| колонка | что значит |
|---|---|
| балл | взвешенное среднее по кейсам этапа, 0–1 |
| ложных | сколько текстов помечено зря |
| пропущ | сколько рекламных или сгенерированных пропущено |
| с/текст | время на текст, включая загрузку и сеть |

Отчёт пишется в `data/bench/laya.json` рядом с отчётом `bench.py`. Из
интерфейса — задача «Laya против текущей модели».

Цифры прогона — этот прогон на этих кейсах, а не измерение пайплайна [CORE-019].
Решение «заводить ли вторую модель» принимается по своим данным: положи в
`--cases` пару сотен своих отзывов с разметкой.

## Установка

Нужен Python 3.10+ и своё виртуальное окружение (torch тянет ~2 ГБ).

```powershell
cd C:\dev\fuckhr
py -3.11 -m venv .venv-laya
.\.venv-laya\Scripts\python.exe -m pip install laya
.\.venv-laya\Scripts\python.exe -I -c "import laya; print(laya.__version__)"
```

Только CPU (без CUDA, экономит место и не спорит с Ollama за видеопамять):

```powershell
.\.venv-laya\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu
.\.venv-laya\Scripts\python.exe -m pip install laya
```

Первый запуск качает веса с Hugging Face в `%USERPROFILE%\.cache\huggingface`
(мультиязычный чекпойнт ~650 МБ). Проверка и сравнение:

```powershell
.\.venv-laya\Scripts\python.exe laya_bench.py
```

## Включение в пайплайне

По умолчанию выключено: это ещё одна модель в памяти рядом с Ollama.

```
LAYA_ENABLED=1
LAYA_MODEL=convaiinnovations/laya-multilingual
LAYA_THRESHOLD=0.5
```

Те же три поля есть на странице настроек, группа «Гейты и разметка».
Мультиязычный чекпойнт обязателен: английский (`convaiinnovations/laya`) на
русском тексте разваливается — это сказано в README самой Laya.

## Первый замер (23.09.2026, окружение владельца)

Мультиязычный чекпойнт zero-shot, порог 0.5, кейсы бенчмарка:

| этап | кейсов | балл | ложных | пропущено | с/текст |
|---|---|---|---|---|---|
| `review_fake` | 3 | 0.2 | 6 | 0 | 0.194 |
| `ai_text` | 3 | 0.2 | 3 | 0 | 0.272 |

Ни одного пропуска и ни одного молчания: решатель отвечает «да» почти на любой
текст, включая живые отзывы и человеческую вакансию. Это ровно то, о чём
предупреждает README Laya — базовые чекпойнты без дообучения ниже
majority-class. Скорость (0.2–0.3 с на текст на CPU) при этом приличная.

## Второй замер: порядок вариантов (23.09.2026)

`--sweep` теперь задаёт каждый вопрос дважды — с вариантами в прямом и
перевёрнутом порядке, одним вызовом `predict` (`laya_judge.pair`) — и пишет в
лог AUROC для обоих порядков. Порог двигает только точку отсечения; если при
перевороте ранжирование переворачивается, решает позиция, и порог не поможет.

| этап | AUROC прямой | AUROC перевёрнутый | вывод |
|---|---|---|---|
| `review_fake` | 0.933 | 0.067 | отвечает по позиции варианта, а не по смыслу |
| `ai_text` | 0.833 | 0.833 | вопрос читает, но вероятности 0.4–0.7 |

То есть рекламные отзывы энкодер от живых отличает, но к смыслу вопроса это не
привязано: при прямом порядке «реклама» ложится на «да», при перевёрнутом — на
«нет». Лучший порог на `review_fake` (0.6) даёт балл 0.4 с ложным
срабатыванием; на `ai_text` при 0.7 решатель просто молчит (балл 0.6 — это
молчание на ловушках). Усреднять два порядка нельзя: сигнал гасится (AUROC 0.4).
Температуры у мультиязычного чекпойнта не подобраны (`[1, 1, 1]`), поэтому
вероятности не калиброваны. Кейсов 21 текст — это диагноз, не измерение
[CORE-019].

## Как внедрять

Zero-shot не включается. `LAYA_ENABLED` пока ни к одному этапу не подключён.

1. **Данные.** `dataset_export.py` отзывы и `ai_text` сознательно не выгружает:
   в `review_items` лежит выдержка в 240 символов (`docs/dataset.md`). Нужно
   хранить полный текст, который видела модель, рядом с её вердиктом — это
   разметка учителя. Поправки владельца весят больше вердиктов модели.
2. **Дешёвая проверка до Laya.** Логистическая регрессия на векторах bge-m3,
   которые уже считаются (`embeddings.py`), с теми же метками. Если она на
   отложенной выборке не хуже дообученной Laya — вторая модель не нужна.
3. **Дообучение.** Официальный ноутбук
   `notebooks/laya_finetune_typed_decisions_2xT4_kaggle.ipynb` (Kaggle 2×T4,
   бесплатно) от `laya-multilingual`; температуры — на отложенной части.
   Результат — локальная папка в `LAYA_MODEL`. Критерий приёма: `order_check`
   на своих `--cases` даёт AUROC ≥ 0.7 при обоих порядках.
4. **Подключение гейтом, а не заменой.** Уверенное «да» или «нет» — модель не
   зовём, середина или расхождение порядков — этап идёт через шлюз как сейчас.
   Экономит вызовы [CORE-016] и не теряет решения. Laya грузится на время
   этапа и выгружается (`Agent` — контекстный менеджер), чтобы не держать её
   рядом с Ollama весь прогон.

Чего не делать: `laya-serve` и Hosted API — второй HTTP-клиент к моделям в
обход шлюза [CORE-010]; `Router` — все тексты русские, он всегда выберет
мультиязычный чекпойнт; тип `score` — позиционное смещение (#131).

## Что знать до включения

- По бенчмаркам автора базовые чекпойнты на типизированных решениях **ниже
  majority-class** (0.34–0.36 против 0.46); вся способность появляется после
  дообучения. Данных на дообучение этих двух этапов пока нет (шаг 1 выше).
- Известные баги README: `noul` залипает на метках вариантов (#156) — поэтому
  вопросы здесь заданы как `choice` с нейтральными ключами; у `score` на
  мультиязычном чекпойнте позиционное смещение (#131) — этот тип не используем.
- Русский в отдельных цифрах автора не выделен, так что пока модель зовут
  «непроверенной на нашей задаче».
- Нет пакета или весов — этапы считаются как раньше [CORE-017], пайплайн не
  падает и в лог пишется одна строка.
