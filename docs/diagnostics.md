# Диагностический прогон

Обычный лог написан для чтения глазами: строки, пороги, ошибки. Когда
результат выглядит странно — «собрал не то», «баллы у всех одинаковые»,
«модель молчит», — по нему приходится гадать, потому что чисел, по которым
проверяется гипотеза, в нём нет.

Диагностический прогон пишет эти числа отдельно: `data/diag/run-*.jsonl`,
событие на строку. Файл рассчитан на то, чтобы отдать его целиком — себе через
месяц или помощнику.

## Как включить

Галочка «Диагностический прогон» в настройках (группа «Запуск»), ключ
`DIAG_RUN`, либо разово:

```powershell
.venv\Scripts\python run.py --diag
```

Включать на один-два прогона. Дальше выключать: смысл в разборе конкретного
случая, а не в постоянной записи.

## Что внутри

| событие | о чём |
|---|---|
| `начало` | окружение без секретов, рабочая папка |
| `настройки` | лимит, профиль, предфильтр, пороги, включена ли модель |
| `профиль` | запросы, регионы, счёт навыков и стоп-слов, веса, порог |
| `запрос` | площадка, текст запроса, регион, период, сколько нашлось |
| `разбор_страницы` | вакансии взяты из выдачи или со всей страницы (B-27) |
| `вакансия` | ключ, название, компания, вилка, график, опыт, **балл, все причины**, отклонена ли и почему, баллы по каждому профилю |
| `модель` | этап, профиль, исход: ответ, из кэша, ошибка, пропущен, никто не ответил |
| `запрос_сорвался` | площадка и текст ошибки |
| `итог` | сводные счётчики прогона и вызовы модели |

Событие `модель` пишется на каждую попытку, а не на каждый этап. Неудачная
попытка кандидата — это реальный поход в сеть и строка бюджета, и её видно:
маршрут, модель, номер кандидата, номер попытки из скольких, статус ответа,
повторяемая ли ошибка и её текст (с вырезанными ключами). Без этого «вызовов
модели 128» в итоге не сходилось с числом событий в файле, и причина падений
кандидата оставалась только в обычном логе. Исход `пропущен` — этап выключен
или кончился бюджет.

## Чего в файле нет

Секреты из окружения заменяются на «задано» или «пусто»: ключи, токены, куки,
пароли, прокси. Контакты людей, тексты отзывов и описания вакансий целиком не
пишутся — только длина и признаки [CORE-012], [CORE-013]. Поэтому файл можно
пересылать, не вычищая руками.

## Быстрая сводка

```powershell
.venv\Scripts\python diag.py
```

Печатает по последнему файлу: сколько событий каждого вида, что нашлось по
каждому запросу, распределение баллов (минимум, медиана, максимум и сколько
среди них различных — одинаковые баллы у всех сразу видно), причины отказов по
частоте, исходы вызовов модели по этапам и десятку самых частых сбоев модели
(маршрут, модель и текст ошибки).

## Границы

Запись ограничена `MAX_EVENTS` строк (5000), дальше пишется только итог: ночной
прогон на тысячу вакансий не должен оставить гигабайт. Выключенная диагностика
стоит одной проверки булева поля на событие, поэтому хуки стоят прямо в
горячих местах. Ошибка записи выключает диагностику молча — прогон важнее
следа [CORE-017].
