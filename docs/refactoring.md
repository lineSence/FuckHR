# Рефакторинг структуры (29.09.2026)

План и журнал одного рефакторинга. Цель — упростить разработку, не меняя поведения:
все тесты зелёные после каждого шага, пайплайн и интерфейс работают как раньше.
Шаги идут по порядку, каждый — отдельный коммит в ветке `refactor/structure`.

Корень проблемы: границы между частями системы нигде не записаны и не проверяются,
а единственное структурное правило ограничивает размер файла, а не связность.

## Принципы

- Поведение не меняется. Рефакторинг — это перенос и разрезание, а не переписывание логики.
- Имена файлов сохраняются: `llm.py` остаётся `llm.py`, меняется только папка.
  Ссылки в документации по имени файла остаются верными.
- Граница пакета — правило, которое проверяет тест, а не договорённость.
- Никаких новых зависимостей в рантайме (`[CORE-025]`).

## Шаги

Готово, когда: корень без дампов, CI-конфиг в репозитории, тесты зелёные.

### Шаг 2. Разорвать циклы импортов

Каждый цикл рвётся переносом кода туда, где ему место, а не ленивым импортом.

- [x] `settings` ↔ `reviewsites`/`review_area`: каталог настроек не импортирует предметные модули;
      списки в подсказках — литералы, их актуальность проверяет тест.
- [x] `settings_fields` → `llm`: каталог берёт имена этапов из `llm_profiles` (чистые данные).
- [x] `bot` ↔ `run_setup`: `setup_logging` и `quiet_libraries` — в отдельный модуль `logs.py`.
- [x] `outreach` ↔ `outreach_scan` ↔ `llm_tasks`: лимит письма передаётся параметром;
      запуск этапа контактов (CLI, Telegram) уходит из `outreach.py` в пайплайн.
- [x] `collector` → `hh_pages` → `profiles` → `collector`: `worth_details` переезжает к скорингу профилей.
- [x] `geo` ↔ `hh_html`: `geo` разбирает состояние через `hh_parse`, дозаполнение адресов — в `geo_backfill`.
- [x] `dossier` ↔ `dossier_*`: импорты только для аннотаций (`TYPE_CHECKING`) циклом не считаются;
      остальные связи проверяются тестом.

Готово, когда: ноль циклов по всем импортам, включая импорты внутри функций.

### Не входит, нужно решение владельца

- **Страховка этапов прогона.** Сейчас исключение в любом этапе `AFTER` роняет прогон, как и до
  рефакторинга. Обернуть необязательные этапы (векторы, контакты, оценка работодателя) в
  «залогировать и идти дальше» — одна строка в `run_once`, но это меняет поведение, а шаг 5
  поведение не меняет.

- **Заморозка скоупа.** Пока идёт упрощение — никаких новых функций. Кандидаты на удаление,
  если ими не пользуются: `lab/` целиком, стилометрия `ai_text_rules`, разметка спанами `extract_spans`.
- **Аудит 116 настроек.** Настройки, которые никто не меняет, стать константами.
  Какие именно — знает только владелец.

## Журнал

Заполняется по ходу: что сделано на шаге, что пошло не по плану.

**Шаг 1.** Удалены 7 дампов (~1,5 МБ), `/*.html` в `.gitignore`. `ruff` с минимальным набором сразу нашёл настоящую ошибку: `tests/test_review_gate.py` использовал `pytest` без импорта. CI: `.github/workflows/ci.yml`.

**Шаг 2.** Все 5 циклов разорваны переносом кода, ни одного нового ленивого импорта:
- `logs.py` — `setup_logging`, `quiet_libraries` (были в `run_setup`, из-за чего `bot` и шесть других модулей тянули пайплайн).
- `settings_base.py` — `Field`, виды значений и имена групп; `settings_fields_extra.py` удалён, сборка каталога — в `settings_fields.py` без импорта снизу файла. Каталог больше не импортирует `llm`, `reviewsites`, `review_area`; литералы сверяет новый тест.
- `reviewtext.py` — HTML → текст и «похоже ли на отзыв»: нижний уровень под `reviewitems` и `reviewpage`.
- `outreach_run.py` — CLI этапа контактов с отправкой в Telegram; `company_hits`, `find_contacts`, `pages_from_hits` переехали в `outreach_scan`; лимит письма в `llm_tasks.polish_draft` — параметр.
- `worth_details` — из `hh_pages` в `profiles`; `geo` разбирает состояние через `hh_parse`.
- Не по плану: внутри каталога настроек нашёлся шестой цикл (`settings_fields` ↔ `settings_fields_*`), его не было видно в первом замере, потому что он сливался с большим.

**Шаг 3.** 177 модулей в 12 пакетах, `git mv` — история файлов сохранена. В корне из кода только `run.py` и `webui.py` по 7 строк. Логгеры сохранили прежние имена (`getLogger("db")` вместо `__name__`), чтобы лог и фильтры не поменялись. Фоновые задачи интерфейса запускают `python -m fuckhr.<пакет>.<модуль>`. Проверка: 783 теста зелёные; все модули импортируются; 16 страниц интерфейса отдают те же коды и тот же HTML, что до рефакторинга, кроме подсказок с командами запуска.

**Шаг 4.** `tests/test_architecture.py` (5 тестов): граф 178 модулей / 627 рёбер по AST, слои из `LAYERS`, поиск циклов, в корне только запускалки, самопроверка на подложном графе. Проверено вручную: ленивый `from fuckhr.web import ui_core` внутри `core/db.py` роняет два теста. `[CORE-024]` переписан по поручению владельца (`[CORE-003]`): связность вместо размера. 87 упоминаний «25 КБ [CORE-024]» в старых докстрингах не переписывались: новое правило прямо называет их историей. Карта кода — `AGENTS.md` §2a и `docs/architecture.md` «Пакеты и слои».

**Шаг 5.** `run_once` — 17 строк: `start` → `COLLECT` (5 этапов, внутри `try` на капчу) → `close_network` → `AFTER` (10 этапов) → `finish`. Состояние прогона — dataclass `Run` вместо 25 локальных переменных. Самая длинная функция — `start`, 56 строк (было 450 в одной). Цена: `run.py` вырос с 640 до 794 строк за счёт сигнатур и докстрингов этапов. Проверка сверх тестов: 5 сценариев (полный прогон, повторный с исчезнувшей вакансией и `--diag`, без описаний с лимитом и штрафом работодателя, капча посреди сбора, выключенные детектор и оценка) прогнаны на коде до и после — лог, stdout и дамп всех таблиц базы совпали построчно.

Шаг 6. `do_GET`/`do_POST` в `fuckhr/web/webui.py` — по 15 строк: поиск в таблицах `GET_BARE` (без базы: /, /settings, favicon), `GET` (с открытым соединением) и `POST`; разделы с несколькими формами (`/gate/*`, `/targets/*`, анкета профиля) разбирает `post_group`. Каждая ветка стала функцией `get_*`/`post_*`; файл 686 → 746 строк. Порядок проверок сохранён (точные адреса и префиксы не пересекаются — проверено). Сверка до/после: 26 GET-адресов (включая неизвестные, POST-only и пустые параметры) — коды и HTML совпали байт в байт, кроме пути к временному .env; 25 POST-форм с заголовками Origin — коды, Location, тела, .env и дамп базы совпали (кроме меток времени). 788 тестов зелёные.

Шаг 7. README переписан: что это, цель по `[CORE-018]`, запуск, таблица «где что» (123 → 52 строки); пересказ стека и таблица «чего нет из ADR» ушли в `docs/architecture.md` («Расхождения с ранними ADR», объединена с таблицей из `wiki/architecture/tech-stack.md`, там — ссылка). «5 вакансий с полным досье» убрано из README и ADR-004 в `overview.md`. Уточнение к диагнозу: README с `[CORE-012]` не расходился — флаг `LLM_PERSONAL_VIA_PROXY` и есть «настройка владельца»; расходился `wiki/architecture/pipeline.md` («данные о людях — только локальной моделью»), исправлен, пункт плана поправлен. В `overview.md` таблица модулей заменена ссылкой на карту пакетов, «без CSRF-защиты» → `ui_guard`. `pipeline.md`: схема этапов — ссылка на `run.COLLECT`/`AFTER`, нумерация шагов и «модель только в трёх местах» убраны. В `docs/architecture.md` исправлено «Векторов нет», добавлена таблица CLI-команд (все 11 проверены `--help`). 33 команды `python <модуль>.py` в 16 файлах → `python -m fuckhr...`; `outreach.py` как CLI → `outreach_run` (contacts.md, pipeline.md, architecture.md). `docs/roadmap.md`: долг по `[CORE-024]` закрыт. `docs/contributing.md`: куда класть модуль, ruff+pytest перед PR, как добавить страницу и этап, правило одного источника. `wiki/architecture/map.md`, `targets.md`: ссылки на `docs/` и пометка об истории «25 КБ».
